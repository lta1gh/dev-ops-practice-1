# 1. Почему в GIT ветвление "дешевое", а в SVN "дорогое"?

Это связано с тем, что GIT использует систему контроля версий на основе снимков (snapshots), где каждая ветка хранит только изменения относительно предыдущей версии. Ветвление в GIT создается быстро и занимает мало места, так как новые ветки создаются как ссылки на существующие коммиты.

# 2. Можно ли в SVN сделать коммит без интернета? Почему?

Нет, в SVN нельзя сделать коммит без интернета, так как SVN является централизованной системой контроля версий. Все изменения должны быть отправлены на центральный сервер, чтобы сохранить историю проекта. Без подключения к серверу невозможно выполнить коммит.

# 3. В каких сценариях SVN до сих пор может быть предпочтительнее GIT?

1. Центральное управление: В проектах, где требуется строгий контроль над доступом и централизованное управление версиями, SVN может быть предпочтительнее.
2. Простота использования: Для небольших команд или проектов с ограниченным числом участников, где не требуется сложная ветвление и слияние, SVN может быть проще в использовании.
3. Интеграция с существующими инструментами: В некоторых организациях уже используются инструменты и процессы, интегрированные с SVN, что делает его более удобным для таких сценариев.
